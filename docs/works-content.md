# إضافة المحتوى إلى «أعمالنا»

تُقرأ البيانات من `assets/works-data.json`. يحتوي الملف على قائمتين، `translations` و`releases`. القائمتان فارغتان حاليًا. أضف المحتوى الذي يعتمده صاحب الموقع ثم ارفع الملف إلى GitHub. تبقى الواجهة نفسها عند إضافة عناصر جديدة.

## تعريب جديد

أضف كائنًا إلى `translations`. هذا قالب للحقول، وتُستبدل قيمه بمعلومات المشروع الفعلية قبل نشره.

```json
{
  "id": "project-id",
  "title": "",
  "cover": "",
  "platform": "",
  "status": "",
  "description": "",
  "overview": "",
  "emulator": "",
  "includes": [],
  "requirements": [],
  "patchSteps": [],
  "launchSteps": [],
  "downloads": [],
  "sources": [],
  "troubleshooting": [],
  "extra": []
}
```

- `id` معرّف فريد بحروف إنجليزية صغيرة وأرقام وشرطات. يُستخدم في رابط `translation.html?id=project-id`.
- `title` الاسم الرسمي. `platform` الجهاز. `status` النص الذي يحدده صاحب المشروع، ويُعرض كما كُتب.
- `description` وصف موجز مطلوب للبطاقة. `overview` نبذة أطول اختيارية.
- `cover` رابط الغلاف أو مساره داخل الموقع. يُعرض بديل مرسوم إذا غاب الغلاف أو تعذّر تحميله.
- `includes` و`requirements` قائمتان نصيتان.
- `patchSteps` خطوات تطبيق الملفات، و`launchSteps` خطوات التشغيل الخاصة بهذه اللعبة والمحاكي. كل خطوة نص مستقل، وتُحافظ الأسطر الجديدة على ترتيبها.
- `downloads` و`sources` قائمتا روابط. لكل رابط `label` و`url`. تُستخدم الروابط المقدمة من صاحب المشروع.
- `troubleshooting` و`extra` قائمتا معلومات. لكل عنصر `label` و`text`.
- الحقول الاختيارية `version` و`releaseDate` و`progress` تعرض رقم النسخة وتاريخ التعريب بصيغة `YYYY-MM-DD` والنسبة من 0 إلى 100. أضفها فقط عندما يحددها صاحب المشروع.
- يظهر البحث عند توفر أربعة مشروعات. يظهر كل مرشح عندما تتوفر أكثر من قيمة للجهاز أو الحالة.

## موعد إصدار

أضف كائنًا إلى `releases`، واستبدل القيم بمعلومات الموعد المعلن رسميًا.

```json
{
  "id": "release-id",
  "title": "",
  "cover": "",
  "platforms": [],
  "date": "",
  "region": "",
  "timeZone": "",
  "source": "",
  "note": ""
}
```

- `date` تاريخ الإصدار بصيغة `YYYY-MM-DD` في منطقة الإصدار.
- `region` وصف المنطقة بالعربية، مثل «السعودية» أو «إطلاق عالمي».
- `timeZone` اسم منطقة IANA مثل `Asia/Riyadh` أو `America/New_York`. في الإطلاق العالمي المتزامن، اختر منطقة العرض بوضوح.
- `source` رابط الإعلان الرسمي المطلوب لكل موعد.
- عندما تُعلن ساعة الإطلاق، أضف `instant` بصيغة ISO 8601 كاملة مع `Z` أو إزاحة زمنية صريحة. يجب أن يطابق يومها قيمة `date` بعد تحويلها إلى `timeZone`.
- عند غياب الساعة، احذف `instant`. يعرض القسم فرق الأيام التقويمية وفق منطقة الإصدار، وعبارة «وقت الإطلاق لم يُعلن».
- للمواعيد المختلفة بين المنصات أو المناطق، أضف بطاقة مستقلة لكل موعد مع معرّف مستقل. للمواعيد المشتركة، اجمع المنصات في `platforms`.
- عند تأجيل الإصدار، عدّل `date` و`instant` عند وجوده والمصدر معًا. يعيد التقويم توزيع الموعد تلقائيًا.
- التقويم ميلادي، ويبدأ من الشهر الحالي للزائر. توضع كل لعبة في تاريخ منطقة إصدارها. اختيار يوم يعرض إصداراته، والضغط عليه مرة أخرى يلغي التحديد.
- يحسب العد الدقيق الفرق بين اللحظة الحالية وموعد الإطلاق. عندما يحين الموعد يظهر «صدر اليوم»، ثم «صدرت» في الأيام التالية بحسب منطقة الإصدار.
- يتوقف تحديث العد عندما تكون الصفحة مخفية، ويعود مع الوقت الفعلي عند الرجوع إليها. يعمل الحساب من ساعة جهاز الزائر.

## الفحص والنشر

نفّذ `node --test tests/works.test.cjs` لفحص منطق التواريخ والمناطق الزمنية. نفّذ الاختبارات العامة في المستودع ثم `python scripts/build-performance.py` قبل الرفع إذا عدّلت ملفات مشتركة أو صفحات HTML.

الصفحتان `works.html` و`translations.html` وصفحة `releases.html` هي المداخل الرئيسية. صفحة `translation.html` تعرض تفاصيل المشروع المحدد في الرابط. تفاصيل الغرض المرئي موثقة داخل `identity.html#guide-works`.

بطاقتا «قريبًا» و«قيد التحضير» موجودتان في `works.html`. عند اعتماد محتواهما، استبدل كل بطاقة برابط إلى صفحتها الفعلية، واحتفظ بالمعنى المقروء لعنوانها.
